# 阶段一：想清楚

这一阶段定下：这是什么汇报、讲给谁、主角是谁、分几部分、每页讲什么。定位偏了，后面怎么调版面都不对。
产出：场景卡、选好的材料、架构。架构要等使用者确认。

## 一、场景卡（开工先问清，写成文件放在项目文件夹里）

```
汇报类型：课程总结／课上文献汇报／其他
时长：讲 X 分钟＋讨论 Y 分钟
听众：谁，基础如何，是否同一方向
评委：谁，关心什么
老师要求原话：（粘贴）→ 必须落页的关键词：①… ②…
主角：这次汇报讲的是谁的东西（课程／这篇论文）
总问题：这次汇报要回答的一句话
模板：路径（只取外壳）
参照成品：路径（样式和密度照它）
素材：文件夹路径
截止：日期
屏幕：投影（颜色发灰，要深字白底）／液晶屏
特例：只对这一次有效的要求
```

一次问一个问题，给选项。缺的信息能自己从文件里找到的，就不问。

## 二、两类汇报的区别

| | 课程总结汇报 | 课上文献汇报 |
|---|---|---|
| 主角 | 课程主线加自己的理解 | 这篇论文 |
| 结构 | 按主题分 3–4 部分，每部分 现状 → 问题 → 路径，最后体会 | 是什么 → 为什么 → 怎么做 → 结果 → 原因、价值与不足 → 讨论 |
| 材料怎么用 | 课上核心观点要用，但重新组织；自己补的数据、案例不超过一半 | 只用原文；我们补的内容集中放到后面，标明是“我们的” |
| 容易出的错 | 复述课程；照搬老师课件的问句标题 | 为显得丰富而补论文以外的内容 |

这两类各有一个完整案例（`examples/`）。其他类型的汇报我们还没用这套方法做过。

课程总结汇报：
- 课上的内容要充分用，否则显得没听课；但不按老师的顺序复述，重新提炼成表、对比、流程。
- 老师讲过的长案例只取支撑本页的 2–4 个要点。
- 每部分讲完收获，加一句和自己研究的结合；用到课题组的数据要说明出处。
- 体会集中放 1–2 页，用使用者自己的话，只删减、顺句，不替他加意思。
- 老师名字不上屏。

课上文献汇报：
- 必须有独立的页：论文关注的问题（单独列 2–3 个）、结论与创新点、研究不足（作者自述的，加上“我们的疑问” 1–2 条）。
- 作者说的和我们说的分开写。
- 内容基于原文，拿不准就回原文找；不补论文以外的数据和图。

## 三、选文和读材料

- 选文献：先写下选择标准，再逐条比候选。我们用的标准：和课程贴合、5 分钟讲得清、证据硬（现场实测优于模拟）、贴近自己的课题、听众接得上。给推荐时说出“哪个因素一变，结论就翻”。
- 精读：让使用者和联网的 AI 一步一停地读，每步停下等他提问。看图先看坐标、单位、图例、比较基准和时段，再看支撑结论的具体曲线或单元格。读完出一张交接卡：研究问题、方法、核心数字和出处、作者说的不足、读者的疑问。精读时使用者问出来的问题，往往比 AI 的总结更有用，后面大多会进 PPT。
- 课程汇报：先把课件、笔记、录音转写过一遍，列出每一讲讲了什么。

## 四、搭架构

给 2–3 个方案和你的判断，等使用者确认。可以用的方法：

1. **来源 × 主题矩阵**：行是各讲或各篇材料，列是要讲的几件事。多个来源都有的列是主线，只有一个来源的格子做补充，空格要么补材料、要么不讲。用来避免“第一位老师讲了……第二位老师讲了……”。
2. **现状 → 原因与意义 → 做法**：每部分按这三段走，不必等长，材料多在哪段就多给页。老师或课程给过一组问题时，优先用他们的问题做骨架。
3. **金字塔**：先写总问题，分成 3 个左右互不重叠、合起来能回答总问题的子问题。检验：目录几项能否并列、有没有交叉。
4. **按听众理解的顺序**：讲 PPT 和写论文是两回事，不照搬论文章节。

单页写法：标题写正式页名（编号＋名词短语），标题下 1–2 条一行的要点句写结论，正文用图、表、数字做证据。

要不要单独成页：这一页能回答所在部分的子问题吗？它有不可替代的作用吗？两个都否就合并或删掉。同一主题的页放在相邻位置。

架构定稿的检验：
- 只读各页标题，能连成一条线；
- 部分之间不重叠，论点不在两部分重复；
- 老师要求的关键词都有对应的页；
- 页数合适（见第五节）。

## 五、页数和字数（我们两次的实际数字）

- 内容页数约等于时长（秒）÷ 30。8 分钟课程汇报做了 13 页内容页，加封面、目录、分隔页、体会、致谢共 19 页；5 分钟文献汇报讲论文 12 页，每页约 25 秒，方法页 15–20 秒带过。
- 屏上字数：只算标题、要点和正文，每页约 150–250 字；连图注、标签、来源一起算，约 300–400 字。
- 内容超了先删字、合并页，不缩字号。

## 六、讨论问题页（需要互动时）

标准：
- 听完汇报就能参与，不需要现场算数，也不需要掌握具体成本数据；
- 能用课上讲过的原理推理；
- 各个方向的同学都有话说；
- 有收得住的参考答案，但不提前写在页面上。

找问题的方法：
1. 把论文的效果拆成几个决定因素（例：碳排放 ≈ 热需求 ÷ 转换效率 × 碳强度 − 可再生抵扣）。
2. 看论文分别动了哪一项，靠的是什么条件。
3. 换一个条件问：搬到我们的场景，哪些还成立，哪些要改，哪些行不通。

讨论问题页放问题、几个思考方向（各配一句提示）和相关公式，不画框，不列备选问题。讨论小结页按同样的方向逐条写文字，最后一句红字收住。最好的问题常常是使用者自己想出来的：你负责把思路拆清楚，给方向和判断标准。
