# 阶段四：交付与积累

这一阶段把 PPT 收尾交出去，再把这次的纠正记下来，让下一次少改几轮。

## 一、备注

- 屏上文字定稿后统一写，写稿阶段只留一行要点。
- 备注是讲的时候的提醒，要能直接说出口：只写屏上没有的补充、过渡和口径提醒，正式汇报语气；不写开场白、元叙述，不写成讲稿。
- 全篇约每分钟 120 字（7 分钟汇报约 800–1000 字）。
- 提到老师讲过的内容，顺口带一句即可；不写防御性的口径说明和与主题无关的信息。

## 二、外部意见（可选）

成品基本做完后，可以写一段评审提示词，让使用者发给其他 AI：

```
附件是一份 X 分钟的【汇报类型】PPT 的总览图和场景卡。听众是【谁】。
请站在台下听众的角度，指出最影响效果的 3–5 个问题（定位、逻辑、重点、可读性），
每条说清在第几页、为什么、怎么改。不提字体、颜色这类细节。
```

意见回来后由使用者挑选，只采纳他挑出来的；你也要有自己的判断，不被带偏。我们文献汇报时采纳了两条（结果页合并；讨论问题不能要求现场算数）。

## 三、改动审查

使用者认真从头审的轮数有限，中间多是一眼看过去就改。每部分写完、全篇定稿前，各做一次：

```
对比改前和改后的文稿（或 PPT），逐条列出：
1 改得好的：保留
2 可能没看清、原版更好的：建议改回，说明理由
3 方向对但改过头的：给折中写法
只列有判断价值的，不复述全部改动。
```

## 四、交付

- [ ] 老师要求的关键词都有对应页
- [ ] 只读标题能连成一条线
- [ ] 每页有具名案例或数字，有来源
- [ ] 没有〔待核实〕、占位框、模板水印
- [ ] 屏上文字和备注都按写作规范过了一遍
- [ ] 图片压缩过（`scripts/compress_pptx.py`，长边 1800 像素；我们一份 60 MB 的文件打不开，压到 22 MB 后正常）
- [ ] 导出了 PDF 备份（`scripts/topdf.ps1`）
- [ ] 在 WPS 或 PowerPoint 里实际打开过
- [ ] 文件名带日期和版本；改动前的版本另存保留

## 五、把这次的经验记下来

规则分三层，放在不同的地方：

| 层 | 是什么 | 放在哪 |
|---|---|---|
| 长期规则 | 换任何汇报都成立的做法 | `流程/` 里的四个文件 |
| 个人偏好和样式 | 某个人的字体字号、配色、参照成品、说过的喜好和反感 | `可调设置/` |
| 当次设置 | 这一次的页数、时长、听众、屏幕、特殊要求 | 项目文件夹里的场景卡，不带到下次 |

判断方法：问“下次换一个汇报，这条还成立吗”。成立的是长期规则，只对这个人成立的是个人偏好，只对这一次成立的是当次设置。
例：“文献汇报的主角是论文，不补原文以外的数据”是长期规则；“讨论问题搬到华北日光温室和牛舍”和“5 分钟 12 页的分法”只对那一次有效。

怎么记：
- 使用者每纠正一条，当场记进 `可调设置/个人偏好.md`，后面的页照着做，同类错误不犯第二次。
- 每条一行：规则＋原话或原因＋日期。例：表格相同项合并单元格，不写“同左”（用户：“不礼貌、懒”，11-19）。
- 同一条出现第二次，或者原因能迁移到别的汇报，再升级为长期规则，改 `流程/` 之前先问使用者。

交付后复盘一次，回答四个问题：本来想达到什么？实际怎么样？差在哪，为什么（挑返工最多的两三处）？下次保持什么、改什么？只补 1–3 条新规则，不写流水账。
我们两次复盘得出的、最省返工的几步：开工问清场景，文稿写成具体上屏内容，每轮渲染看图。
