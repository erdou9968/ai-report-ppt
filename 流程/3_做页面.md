# 阶段三：做页面

这一阶段把定稿的逐页文稿做成 PPT。看起来像人做的，靠的是两样：照着参照成品做，每次生成后自己先看渲染图。
产出：第一版完整 PPT 和总览图。自己检查改过一轮以后，再交给使用者看。

## 一、拿参照，定样式表

1. 向使用者要一份他认可的成品 PPT（自己的、同门的、往届的），和学校或课题组模板。没有参照成品，就用 `examples/` 里的两份。
2. 统计参照成品的内容页：字体、各级字号、颜色、行距、形状（圆角、线宽、虚线、渐变、透明度）、每页字数和图片数。可以用 `scripts/extract_style.py 参照.pptx 报告.md --pages 4-15`。
3. 把参照渲染成图看一遍，记下统计看不出来的：页眉样式、面板怎么摆、图和字怎么配、数字怎么强调、版式怎么交替。
4. 写样式表：先套 `可调设置/默认样式表.md`，再按参照和 `可调设置/个人偏好.md` 覆盖。全篇只从样式表取值。
5. 模板的问题很多，只取外壳：封面、目录、分隔页、致谢、页眉和校徽。模板自带的内容页版式、字号、小色块装饰、智能图形、店铺水印、隐藏文本框都不要；配色换成学校标准色。人做 PPT 也是这样：只用模板的封面、目录、分隔页和页眉，内容页按内容重做。

## 二、版式规则

页面构成：
- 大部分页面有 1–2 张图做视觉中心，约四分之一的页面以图为主；连续没有图的页不超过两页。
- 除标题外正文至少 3 行，信息密度随页面功能变：图多的页字少，总结页字多。
- 版式按内容变，相邻页换结构（左右、上下、箭头流程、表格、2×2、列表加卡片），不要连续都是左右两个框。

框：
- 只给需要框的内容加框；表格、单张大图不再套框。
- 框高按里面的文字行数和图算，不预设固定高度；同一排的框文字行数接近，框底不能空一行。
- 一块内容用一个文本框，小标题和正文写在同一个框里，分段设样式。
- 框样式要有变化：粗线带透明度、浅色渐变底、虚线、上圆下方；标签不全是同一种。
- 留白难调时，把文字改成两行或补一行，不硬拉框。

数字和文字：
- 数字写在句子里，红色加粗，不放大，不配色块。
- 对比用表格（表头着色），流程用箭头连接的面板。
- 表格相同的项合并单元格。
- 一行差一点放不下时，稍微调宽让它放下；数字和单位不要断开；标题不压线。
- 目录每项一个短标题，不加冒号和副标题，相邻项不重复用词。
- 封面不能空，标题可以放大。
- 来源只写文献、书籍、标准、政策，页底灰色小字居中。
- 字的粗细、红字、小字要有层次。

颜色：投影会让颜色发灰。深字白底，对比要大；不用浅色字、浅色细线；浅灰的注释和来源也要够深。

## 三、图片

- 来源顺序：使用者自己的项目和现场照片 → 往届 PPT、组会材料 → 课件（课程汇报全篇老师原图不超过 3–4 张）→ 联网检索的实拍（要页面和直链，下载后核对）。
- 实物用实拍；数据图优先用别人已统计好的现成图表；AI 生图只用于小图标、漫画小人。
- 主图至少占半页；图要一眼看出拍的是什么；照片下 1 行说明主体（哪里、哪家、哪年）。
- 横图不放竖框，不拉伸，按框裁切或等比放到最大。一个图位可以放 2–3 张组图。
- 每张图只在对应位置用一次。英文图配中文图注和图例翻译；借来的示意图注明“一般工况，非本文数据”。
- 占位框写清“待放什么”，交付前清零。

## 四、AI 版式痕迹（不要做）

- 一排放大的数字，各配一个色块（像发布会或数据看板）
- 每页都是等大的三栏卡片
- 只起装饰作用的图标、进度条、大号引言色块、一排同色标签横条
- 每页同一种结构、同一种框
- 竖线分隔的标题，四字对齐的小标题

## 五、生成和检查

1. 用 python-pptx 脚本生成：公共函数放 `scripts/pptlib.py`（样式常量在文件开头，按样式表改），逐页写成函数。改字、换图都改脚本重跑，不手动拖。范例：`examples/02_课上文献汇报/脚本/build2.py`。
2. 每次生成后用 PowerPoint 把每页导出成图（`scripts/render.ps1`，传绝对路径），自己逐页看原尺寸的图；拼一张总览图（`scripts/make_sheet.py`）看全篇。
3. 对照第六节的表逐项查。`scripts/check_deck.py 成品.pptx 渲染图文件夹` 可以先扫一遍框里空白、大块留白、小字、AI 味词句、占位框、模板水印，结果只是提示，最后以渲染图为准。
4. 改完只重看改过的页；最后全篇再看一遍总览。
5. 自己查改过一轮后，再把总览图发给使用者，附三行：改了什么、还拿不准什么、需要他定什么。

`extract_style.py`、`check_deck.py`、`make_sheet.py` 是把我们手工做过的步骤写成的脚本，在两份成品上测过，还没在新的汇报里实际用过。

## 六、第一版的常见毛病

我们两次做 PPT，第一版都有下面这些问题，每次要使用者讲解一两轮才改对。交出去之前自己先改掉。
对照图：`examples/01_课程总结汇报/第一版与最终版对比.jpg`。

| 症状 | 原因 | 预防 | 怎么查 |
|---|---|---|---|
| 大片空白，框底空一行 | 先画固定大小的框再填字；图没按剩余空间放大 | 框高按文字行数算（pptlib 的 est_h）；图放到最大 | 渲染图；check_deck“框里空”“大块留白” |
| 同排几个框一满一空 | 写稿时没按版面控字数 | 同排框文字行数接近 | 渲染图 |
| AI 味版式 | 模型的默认审美 | 照参照成品做；第四节 | 总览图 |
| AI 味文字、新闻腔标题 | 第一稿图快，想留到最后润色 | 第一稿就按 `2_写内容.md` 第四节写 | 读一遍所有标题；check_deck 词句 |
| 字太小、太挤 | 内容超出时长，靠缩字号塞 | 先删字、拆页 | check_deck“小字” |
| 主角跑偏，“不像文献汇报” | 为显得丰富往里加东西 | 场景卡写明主角；补充内容放后面并标明 | 只读标题串一遍 |
| 缺老师要求的页（结论、关注的问题） | 没逐个对照要求原话 | 场景卡列关键词，逐项落页 | 对照场景卡 |
| 图片重复、太小、横图塞竖框 | 裁图反复用；按框硬塞 | 每张图只用一次；主图至少半页 | 图片清单；渲染图 |
| 表格写“同左”“同上” | 偷懒 | 合并单元格 | check_deck |
| 模板残留：水印、隐藏框、小色块 | 模板来源杂 | 只取外壳 | check_deck“水印残留” |
| 断行难看，标题压线 | 宽度刚好不够 | 稍微调宽 | 渲染图 |
| 投影后看不清 | 浅色字、浅色细线 | 深字白底 | 渲染图 |
